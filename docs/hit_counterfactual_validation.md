# 击球模型同状态多动作验证：未通过

本轮先验证击球预测，再决定是否训练策略；验证未通过，未训练策略，未将专家回放冒充策略总流程。现有 H1/H2 只能作为离线预测原型。

## 测试与门槛

在运行前固定门槛：预测接触后前 0.5 秒 ADE ≤ 6 cm、点误差 95 分位 ≤ 15 cm、有效真实接触分支比例 ≥ 75%、至少 3 个独立测试 seed。阈值是本轮工程筛选条件，不能等同于击球成功率。

测试 seed 为 68、36、30，均属于原测试划分，未加入训练或模型选择。每个 seed 先用缓存的左右臂计划通过 canonical `run_episode` 回放，记录快速挥击前约 0.17 秒的场景快照及过去 0.4 秒、9 帧 RGB。所有分支从同一 snapshot 恢复，含机器人 q/qvel、驱动目标、球和工具状态；每个 seed 固定摩擦和初始物理条件。随后在该状态执行原角度/速度、方向 ±8 度、速度 ×0.9/×1.1 共 5 个动作，无右臂主动回击，记录真实 PhysX 轨迹。

执行复用 `envs/_air_hockey/expert.py` 的候选执行与参考生成，以及 runtime 的快照/恢复。采集搜索时间不进入正式演示。未放宽接触条件、未改变失败标签、未改原仿真代码。

**这是特权构造候选的仿真基准，候选生成参考使用仿真状态，不是 RGB 自主规划器。** 世界模型预测输入仍为原始 RGB 与计划动作白名单。恢复到已准备一部分的状态再执行新准备段，会改变执行过程；基线分支也不是原完整专家轨迹的严格续接。此测试验证当前模型能否处理这种同状态再规划，不能用其轨迹差异直接证明原 HDF5 或仿真有错误。

## 已发现的结构限制

当前击球头只得到 RGB V4 输出的历史球位置与自由运动预测，没有整个图像的机器人表示，也没有当前关节位置、速度或跟踪状态。同一击球器目标速度在不同准备姿态下不一定产生相同实际接触速度；新的短准备段会暴露这种差异。因此不能仅凭计划位置、方向、速度和球轨迹保证结果可辨识。这是代码能直接确认的输入缺口，并不证明它解释了所有误差。

下一版需保留机器人视觉运动特征，或输入真实机器人本来就能读取的关节编码器位置/速度，进一步预测接触执行与未击中概率；球的仿真真值仍不得作为部署输入。需要新的独立测试 seed，再验证原状态续接、多动作结果与评分能力。未通过前不训练依赖该模型选动作的策略，也不声称闭环击球成功。
