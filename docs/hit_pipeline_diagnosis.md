# 击球流程诊断与 P2 修改

2026-10-11。目标为先定位 P1 未击中问题，再做小范围修改；没有继续扩大世界模型或做强化学习。

## 问题与实验方法

P1 三个种子中，seed 68、30 未击中，seed 36 双臂成功。可能涉及 RGB 轨迹误差、策略动作组合、候选排序及执行时序。新增 `scripts/diagnose_hit_pipeline.py`，从同一个击球前快照分支测试。各分支共享物理参数、刚体/机械臂状态和驱动目标，重置后独立执行；只用物理接触事件判定是否击中。逐物理步保存球与球拍轨迹，距离仅用于诊断，不用于替代接触标签。

先在前 5 个验证种子试验，再覆盖原有全部 15 个测试种子。诊断中的 PhysX 真值参考与专家意图仅用于对照，不进入实际策略接口。记录的是左臂接触，不是双臂任务成功率。当前初始化仍由专家预先准备，右臂仍由专家控制；这些限制没有消除。

## 全部 15 个测试种子的同状态对照

结果目录：`outputs/hit_pipeline_diagnosis/run_20261011_173459/`。每个种子记录 7 个分支，包含不可行候选，不丢弃失败。

| 版本 / 对照 | 左臂真实接触 |
| --- | --- |
| P1：RGB 参考 + 世界模型排序 | 10/15 |
| P2：RGB 参考 + 原始模仿动作 | 11/15 |
| 保留排序，控制固定提前 20 ms | 8/15 |
| 保留排序，控制固定提前 40 ms | 3/15 |
| 真值参考 + 原有排序动作（仅诊断） | 9/15 |
| RGB 参考 + 专家动作（仅诊断） | 14/15 |
| 真值参考 + 专家动作（仅诊断） | 14/15 |

前 5 个验证种子中，P1 原有排序 2/5、原始模仿动作 3/5；固定提前 20/40 ms 分别 1/5、0/5。最初诊断程序遇到完全不可行候选时提前返回，因此初次汇总只显示 4 个可执行种子；这是报告限制，不能把它当作 4/4 总成功。后续补充分量实验保留全部 5 个种子及拒绝原因，测试 15 个种子也完整保留。

具体证据：

- seed 68 的 P1 排序选择速度倍率 ×1.1 后未击中，保留原始动作则击中；seed 36 两者均击中；seed 30 两者均未发生物理接触。
- 初次验证中的 seed 104、49，即使把 RGB 参考替换为真值，原动作仍失败；保留 RGB、换完整专家动作均成功。动作与执行链路值得优先改进。
- 测试中 14 个通过几何/时序检查的排序候选，在计划接触时刻的 RGB 位置误差平均 1.16 cm、95 分位 1.90 cm，沿运动方向平均绝对误差 0.77 cm、横向 0.83 cm。剩余 seed 12 因准备时间不足被拒绝，不计入位置误差统计。该数据只反映这组短时接管窗口。
- 排序在 14 个可行场景中 12 次选择加速 10% 的候选。H3 排序分数偏好更快推进，但未验证接触能力；当前失败分类也不可靠。不能据此认为加速一定更好。
- 即使实测接触通常晚于计划约几十毫秒，固定提前控制在本对照中反而更差。缩短准备时间同时改变了机器人到位过程，不能仅凭接触延迟加一个常数补偿。

上述种子已用于多个版本报告，不能作为全新盲测或正式泛化结论；15 个场景也不足以证明 11/15 比 10/15 的改善稳定。

## 将时机、速度、方向分别替换成专家标签

结果目录：`outputs/hit_pipeline_diagnosis/run_20261011_174005/`，前 5 个验证种子。基线和仅替换时机、速度、方向的三个版本都为 3/5；完整替换专家动作是 4/5。

seed 104：原动作最小中心间隙超过名义半径和约 22.4 mm；替换速度后缩小到约 2.59 mm，但仍未接触；替换整套动作才接触。seed 59 的原动作触发 TOO_LATE，换时机后能执行但仍未击中，完整专家动作同样失败。说明要联合处理时机、速度、方向与当前机械臂状态，不能将单项误差作为已确定的唯一原因。PhysX 的接触裕量与三维形状意味着名义平面间隙只是辅助数值。

## 已实施的 P2

1. 流程验证默认 `--selection bc`：执行未扰动的模仿动作；自由轨迹预测仍作为策略输入，击球后预测与候选排序仍保存用于分析。若原始动作不可行，保留失败并停止，不默默改为另一个动作。
2. 显式 `--selection world-model` 保留 P1 对照入口；没有修改 H3 网络权重或伪装其性能验收通过。
3. 修复原生双臂执行器的触发条件：`after_strike_handler` 仅在左臂存在真实物理接触时调用。此前距离门槛满足但无碰撞，也可能触发右臂；报告的严格检查仍判失败，但会产生错误后续流程。新逻辑返回 NO_PHYSICAL_CONTACT，不启动右臂。
4. 新增时间/沿向/横向诊断、候选选择测试，并检查距离门槛触发而无物理接触时不会调用右臂。

第一次 P2 双臂实验：`outputs/hit_pipeline/run_20261011_173638/`，seed 68、36 完成双侧真实接触与右臂 1 秒尾段，seed 30 严格判定失败；此前 P1 是 1/3。接触触发修复后还需按最终复核结果记录，不以日志中的 RIGHT_RETURN 字样单独判成功。

完整回归在 GPU 可见环境运行：54 项，48 通过、6 条件跳过。生成数据、日志、权重和视频留在忽略的 outputs 目录；保留用户原有工作区改动。

## 复现

仓库根目录，配置好的 RoboTwin CUDA/Vulkan 环境：

```bash
# 原始排序、策略动作、控制提前量及真值诊断对照
python scripts/diagnose_hit_pipeline.py \
  --policy-checkpoint outputs/behavior_policy/run_20261011_170429_148931/best.pt \
  --split test --episodes 15

# 只拆开时机、速度、方向；专家标签仅作诊断
python scripts/diagnose_hit_pipeline.py \
  --policy-checkpoint outputs/behavior_policy/run_20261011_170429_148931/best.pt \
  --split val --episodes 5 --components-only

# P2 双臂执行，默认也是 bc
python scripts/validate_hit_pipeline.py \
  --policy-checkpoint outputs/behavior_policy/run_20261011_170429_148931/best.pt \
  --episodes 3 --selection bc --device cuda

PYTHONPATH=. python -m unittest discover -s tests -v
```

## 最终修复后复核

最终运行：`outputs/hit_pipeline/run_20261011_174138/`。仍为 seed 68、36 双臂成功，seed 30 未接触并停止；严格任务成功 2/3，P1 相同种子为 1/3。本次只验证这三个完整双臂场景，15 个场景的对照结果仅代表左臂接触。

- seed 68：左臂 0.268 秒、右臂 0.736 秒，结束 1.736 秒；36 帧视频可读。
- seed 36：左臂 0.326 秒、右臂 1.051 秒，结束 2.051 秒；43 帧视频可读。
- seed 30：NO_PHYSICAL_CONTACT，结束 0.321 秒、8 帧；没有 right_return、没有 RIGHT 阶段，右臂搜索步数为 0。

三个场景均只执行候选 0，准备阶段物理步数为 0；JSONL 时间戳严格递增，状态数量与元数据一致；两个成功例均完整保留右臂接触后 1 秒。实际核对见运行目录 `audit.json`，成功视频在对应 `seed_<seed>/policy_execution/preview.mp4`。
