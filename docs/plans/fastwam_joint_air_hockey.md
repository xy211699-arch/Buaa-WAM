# 气垫球联合世界模型与策略方案 J1

日期：2026-10-13。状态：J0/J1 原型已实现并完成首轮训练与仿真，联合收益尚未稳定确认；结果见 [J1 实验报告](../joint_policy_j1_results.md)。后续阶段仍为计划。

依据：[Fast-WAM 原论文](https://arxiv.org/html/2603.16666v2)，以及仓库当前 P2 实验。该方案是任务专用的小模型机制验证，不是论文完整视频 DiT/Action DiT 的复现。

## 设计结论

采用“共享当前状态表示 + 动作生成分支 + 未来轨迹监督分支”。先确认未来监督是否改善真实控制，再研究推理时注入预测未来。已完成的 RGB 自由运动模型 V4 保留为视觉初始化、固定对照和回退版本；H3 和现有 BC 策略保留为历史对照。

Fast-WAM 的动作分支不读取未来 tokens；视频分支与动作分支并非共享所有参数。其联合训练的关键是未来损失能够改善动作读取的当前表示。现有代码却在 `HitPredictor.encode_rgb`、训练缓存中使用 no_grad 并固定整个视觉模型；只把两个头的损失相加、继续使用不可训练的缓存，并不能验证该机制。

本方案先用球轨迹代替完整未来视频监督。这有利于 8 GB 显存与现有数据复用，但测试的是“物理未来辅助表示学习”，不能直接宣称复现了视频联合训练的收益。后续仅在机制有效后增加少量未来视觉潜表示监督。

## 当前问题与研究假设

P2 同状态对照中，15 个原有测试种子的左臂真实接触为：原模仿动作 11/15、H3 排序 10/15；RGB 预测配完整专家意图 14/15。前 5 个验证种子的单项时机、速度、方向替换没有增加接触数，完整专家意图提高一个场景。证据支持进一步研究联合动作与执行状态，尚不足以证明联合训练必然改善性能。

研究假设：未来轨迹监督帮助当前表示保留球速、反弹、球拍到位能力等控制信息；生成式动作头表达完整动作组合，减少连续回归混合不同有效方案的风险。只有每状态一套专家标签时，多峰能力不能凭架构自动获得，需要补充经过质量验证的替代方案。

## 第一版网络与信息流

观测 O：过去 0.4 秒的 9 帧顶视 RGB（20 Hz，训练缩放 320×180），当前六关节的位置、速度、驱动目标差，共 18 维机器人特征。所有当前输入的最后时间戳一致。任务目标 G 第一版固定为向右侧合法球门回球，不增加语言模型。

```text
过去/当前 RGB → V4 初始化的固定视觉特征提取
                             ↓
                   可训练的当前上下文编码器 C(O)
                             ↑
                      当前机器人读数
                             ↓
                     当前表示 z（128 维）
                    /          |          \
                   /           |           \
动作头 P(z,G)     未来辅助头 F(z,G)     条件动力学头 D(z,A_exec)
整套击球意图      专家执行后的未来轨迹   给定已记录动作后的未来轨迹/接触
   ↓                    ↓                       ↓
L_action             L_future                 L_dynamics
   └──────────────共同更新当前编码器 C───────────────┘
```

视觉入口复用 V4 CNN、热图定位与校准，从历史 RGB 提取逐帧视觉特征/估计位置；主 Fast-WAM 风格路径不调用 V4 的未来轨迹输出头。先固定这部分视觉定位，新增可训练的历史编码/融合模块，避免已有定位退化。C 第一版采用两层、4 头、宽度 128 的历史 Transformer，融合机器人 token；真实未来不进入 C。

F 预测专家任务轨迹，不读取专家动作。这与“未来监督、策略只读当前”的机制一致，但 F 表示给定观测和专家行为分布的未来，不是任意动作下的因果动力学。D 读取记录中的执行动作，负责动作条件预测，补足我们原先 H3 的功能。F/D 共用当前表示，输出头可以独立；不能把 F 的未来当成与所选动作必然一致。

P 第一版采用小型条件 Flow Matching 头，生成一套连续高层意图：接触延迟、目标 Y、期望球速、方向修正、速度倍率、控制提前量。直接/近轨反弹模式使用独立分类头，首个闭环试验限制在 DIRECT。一次生成的是六维高层意图，不是关节 action chunk；现有 IK 与轨迹执行器负责低层控制。使用 4 步采样起步，对照 8 步；一次视觉上下文编码可缓存，动作仍需多步生成。并行抽样可在诊断中用，但基础部署每次只采一套，不能靠真实结果挑选。

动作 token 只读取 z 与自身带噪动作；未来 token 只读取 z、自身时间查询及允许的执行动作条件。C 不读取动作/未来，P 不读取真实或预测未来。独立模块即可保证首版信息隔离，不必为此引入大型 MoT。未来分支的梯度仍回到 C；固定视觉前端不更新。

## 未来预测的时间轴与目标

统一以决策时刻 t0 为时间原点：t0+0.05、0.10……1.00 秒，共 20 个球 XY 目标，同时覆盖击球前后和未击中情况。主验收关注前 0.5 秒与真实接触；1 秒作为扩展预测范围，不声称整段都已有可靠监督。

原 H3 按“真实接触后”取监督，新模型采用决策相对时间，避免主输出时间轴依赖事后知道的接触时刻。真实接触时间、接触标签只作监督。未击中仍有真实球轨迹，不能将其未来坐标填成零；合法执行失败时也保存完整观测尾段。如果因 IK/时序不可行导致未执行，标记为拒绝/未执行并单独处理，不能让 D 以为不存在的指令已经执行。

跨右臂接触后的目标：首个数据补采关闭右臂，仅观测左臂后 1 秒。原双臂数据遇到右臂接触前设有效掩码，不能把未建模的右臂控制效果混入左臂动力学。时间戳真实对齐；不在接触点两侧插值，也不把丢帧假装成正常间隔。

## 训练与梯度规则

总损失为归一化后的 L_action + λF L_future + λD L_dynamics + λC L_contact。L_future/L_dynamics 用 masked Huber 或 MSE，位置以桌面尺度归一化；L_contact 使用实际物理接触分类和仅正例的接触时间监督。接触分类头第一阶段服务于诊断，不直接担当候选可靠性门控。

动作 Flow Matching：对真实意图 a 和高斯噪声 ε，构造 aτ=(1−τ)a+τε，目标为 ε−a；τ 是生成噪声时间，与真实决策后的预测秒数完全分开。动作各维仅用训练集统计归一化。

关键约束：

1. 专家样本同时监督 P/F/D；非专家扰动或失败样本只监督 D/接触/执行可行性，不强迫 P 模仿失败动作。F 只监督专家分布，不混入随机失败动作的未来。
2. D 的条件是该轨迹实际执行的记录动作，使用固定标签输入。不能把 P 的预测动作输入 D，再用另一套专家动作产生的未来监督它。
3. 第一阶段不通过 D 的预测奖励反向优化 P，不使用 critic。这样避免策略利用不准确动力学模型的漏洞。联合指共享表示的共同优化，不要求每个损失直接更新所有分支。
4. 实验 A/B 使用相同架构、动作头、视觉初始化、优化步数及训练样本；只改变未来辅助损失和允许的梯度路径。H3/P2 只作外部历史对照。
5. 未来辅助损失必须回传 C；只缓存固定 CNN 的逐帧特征，不能缓存可训练 C 的输出。验证时移除未来分支，固定采样噪声应保持动作输出一致。
6. 对 λ 先按损失及 C 的梯度量级归一化，以验证集尝试少量权重（例如 0.1/0.3/1.0），记录动作/未来梯度冲突与轨迹误差；未来误差更小不自动代表控制更好。

## 数据计划

原 100 个 episode 按既有 70/15/15 种子划分复用，旧测试只作回归。新增数据在独立输出目录、相机与物理配置 SHA256 下记录，不覆盖既有数据，不把多个窗口当作独立场景。

先补 20 个训练状态的最小分支集，每状态约 8 个动作；覆盖原专家、当前策略、时机/速度/方向联合扰动以及合理未击中动作。根据覆盖再扩到 70 个训练状态约 560 条分支。准备状态共享快照及随机物理条件，但跨状态覆盖不同种子、速度、位置、边轨反弹和机器人到位状态。

必须在执行之前保存完整意图与准备/击打控制参数；运行中记录球、球拍、关节与驱动目标及各自时间戳、物理接触和拒绝原因。已有部分失败因缺失计划字段被排除，这次避免事后依赖返回值才能得到动作标签。

保留正式契约：HDF5 原生 action 是下一时刻实测状态；需要动作序列时从 control 读取实际命令。首版高层标签来自执行前意图，不混用这两类数据。图像解码仍复用 data/decode_image_bit.py。

策略模仿标签仅来自原有合格专家/再次验证满足目标的替代方案。物理接触成功并不自动是高质量专家标签；世界模型可使用失败，但不能给失败改成功标签。相同状态若存在多套完整有效方案，保存每套方案及其目标，不平均混合不同计划的分量。

补独立最终测试集初定 30 个新种子，完整场景与分支都不进入训练、归一化、超参选择或候选筛选。运行前锁定种子清单、配置和模型选择规则。

## 分阶段实施与对照

| 阶段 | 内容 | 判断依据 |
| --- | --- | --- |
| J0 | 数据时钟/输入隔离、固定视觉入口、纯动作 FM 基线 A | 正确读数、可训练、P2 对照、真实左臂接触 |
| J1 | 同架构加入 F/D 联合监督，策略只读当前表示 B | 配对场景/3 个训练随机种子的闭环改善及延迟 |
| J2 | 可靠的预测未来条件实验 | 新分支重训、扰动/缺失未来鲁棒性，不能直接解除掩码 |
| J3 | 消除专家准备、补闭环接管数据 | 从固定观察规则或机器人初始状态执行，不读取专家截止时间 |
| J4 | 学习右臂及双臂完整验证 | 双侧真实接触及右臂 1 秒尾段 |

先保持当前专家准备中的接管条件，避免联合训练和初始化变化同时引起结果差异。专家选出的观测截止时间与准备姿态依赖仍需明确报告，不能称为完整自主控制。

联合训练有效性至少比较 A 纯动作与 B 联合未来监督。再做 B-stopgrad：未来损失不回传 C，检查收益是否来自表示学习；保留原 P2 外部对照。若数据预算允许，增加冻结 C 的双头对照，避免把收益误归因于多一个可训练头。

用户笔记的未来门控假设放在 J2：分别训练无未来、正确预测未来、扰动/缺失未来条件。未来门控是可学习残差，默认直接策略通路始终存在。真实未来只用于 oracle 诊断：先定义固定专家计划或固定先行候选，使用该同动作的真实后果；不能先执行策略、取得其未来，再回头决定原动作，也不能给不同候选共享一个不相容未来。不同 oracle 条件模型的结果只是诊断上限，不作为部署成功率。若完整比较需研究自由未来条件，另行设计可重现的两阶段实验。

## 部署流程与闭环边界

第一版部署：历史 RGB/当前机器人 → 当前编码器 C → P 的少步动作生成 → 几何/IK/时序检查 → 原生执行器 → 真实接触检查。F/D 不必前向；需要诊断时旁路调用。V4 固定版本仍可作对照执行器的来球参考；如果实际执行器继续调用 V4 未来输出，必须把它算入延迟，不能宣称整个控制流程已删除所有未来预测。

为避免隐藏这一依赖，首先分别计时“联合模型自身策略推理”和“现有 IK 执行桥接”，将 Fast-WAM 风格的直接策略结论限定在前者。第二阶段执行桥接可复用当前 RGB 估计和轻量短时几何外推；真正移除预测参考依赖需学习/生成球拍目标或实际控制块，单独验证，不能悄悄更换执行器而破坏 A/B 对照。

期望每 0.05 秒更新观测，但现有 evaluate_candidate 是阻塞式准备/击打段，尚不能实现每 0.05 秒安全重规划。首版仍一次高层决策；后续改成可中断准备段、仅执行前 0.05–0.10 秒，并在快速击打阶段设提交点防止来回改变计划。必须显式传入最后 RGB 时间戳、推理延迟与命令时钟，在控制入口重新检查未来时机；不使用固定提前量掩盖延迟。现有右臂专家搜索也需独立计时。

## 8 GB 显存预算

固定 320×180 视觉入口，9 帧，宽度 128、2 层上下文模块，2 层小型动作/未来头，初始 batch=8、混合精度、必要时梯度累积至有效 batch=32；每轮动态跑 C/P/F/D，只缓存固定 CNN 特征。目标可训练参数约 1–3M，实际以实现统计为准。

默认训练与 SAPIEN 渲染分开运行。先跑 100 个训练 step 实测 PyTorch allocated/reserved 峰值、GPU 总占用与吞吐，目标训练进程约 4–5 GiB，给桌面/驱动留余量；这些是预算不是已测数字。超预算依次减 batch、减少 tokens、使用累积，不先砍未来监督。首版不加载大型视频 VAE/T5/6B DiT，不生成完整 RGB 视频。

未来视觉辅助扩展仅采用固定视觉编码器产生的少量未来空间潜表示，并保留球 XY 监督；不将该简化称为完整 Fast-WAM 视频流匹配复现。是否有额外收益需单独对照，不能与 J1 一起增加任务。

## 验证与交付要求

主要指标是配对场景下左臂真实接触、有效击球（目标方向与合法范围），完整测试再报双侧成功与右臂 1 秒尾段。辅助指标含不可行/未执行率、动作误差、决策相对时间轨迹 ADE、接触时间误差、接触分类精度/召回、推理 p50/p95、端到端控制延迟和显存。

训练随机种子建议 3 个，场景种子与模型种子分开。模型选择只用验证集，确认轮次/预算后再锁定新测试；报告所有尝试、条件跳过及场景级区间。旧 3 次成功/失败或旧 15 个种子不作为新泛化证据。联合训练版若不改善控制或明显增加延迟，就保留 A，不能为证明研究假设而换成功条件。

拟新增 joint_model.py、joint_data.py、train_joint_policy.py、joint_air_hockey.yml 及相关测试；保留旧入口。未来信息隔离、两个损失均回到 C、删除未来分支的输出一致性、失败真实未来监督、跨接触掩码及执行命令契约为必要回归。涉及原生执行协议时运行全测试和实际单/多种子仿真。

当前方案阶段没有新增可运行的训练命令；上述拟议文件尚不存在。先实施 J0/J1，并分别汇报模型结构、数据、实测资源及配对控制结果，再决定 J2 门控假设是否值得继续。
