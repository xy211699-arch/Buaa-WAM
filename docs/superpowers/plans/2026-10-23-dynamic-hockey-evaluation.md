# 动态冰球评测实现计划

**目标：**实现用户已批准的三组动态评测：可用反应时间曲线、直接与反弹来球对照、突发变速前后配对对照。只交付代码，不加载或运行真实模型。

**架构：**新增独立的 air_hockey_eval 包。配置、场景清单、评分、动作调度和统计使用 NumPy 与标准库；SAPIEN 和 XPolicyLab 在实际运行入口延迟导入。评测不调用专家选动作，不复用成功样本筛选。冻结对手，控制一侧机械臂，场景真值仅供评分和预检使用。

**技术栈：**Python、NumPy、unittest；实际场景复用 SAPIEN/PhysX 资产与击球器跟随逻辑；策略支持 Python 工厂和已有 XPolicyLab websocket 服务；绘图使用可选 matplotlib。

**授权和范围：**用户已明确要求按讨论方案立即执行，时间上限 90 分钟，跳过实际模型检验，因此不再等待额外设计审批。直接在当前干净 checkout 的开发分支实现，不创建另一个用户未要求的 worktree，不改 XPolicyLab 子模块，不安装模型依赖。

## 任务一：冻结协议与配对场景

编写并运行失败测试，覆盖稳定种子、三个场景族、配对保持初始条件、几何不可行时明确报错、清单指纹防篡改，以及非有限值与未知配置字段拒绝。实现 schema.py、suite.py 与默认配置。候选场景必须在无策略的真实 PhysX 参考轨迹预检后才能作为正式运行输入，记录实测 TTC 和反弹数，不能按专家成功筛选。

## 任务二：评分和延迟控制

编写失败测试，覆盖未接触不能成功、跨线插值、违规覆盖成功、超时与模型错误、旧动作在推理期间继续执行、过期动作段丢弃、最新段替换及有界队列。实现 metrics.py、control.py 与 runner.py。真实模式由后台策略线程推理，物理在等待时推进；零延迟模式必须单独标记，不得混合比较。

## 任务三：真实场景与策略边界

实现 sapien_backend.py，复用本仓库实体资产、1000 Hz 物理、俯视 RGB 和末端跟随击球器，按实际关节限位、基准速度限位和工作区判违规，右臂固定。实现 policies.py，将统一 RGB/机器人状态观测接到 Python 工厂或 XPolicyLab websocket；球真值、随机种子、未来轨迹不进入观测。显式配置相机别名，不生成不存在的腕部观测。

## 任务四：可恢复运行和报告

编写失败测试，覆盖断点重复、不同清单或协议拒绝恢复、失败计入分母、缺失样本不能冒充完整结果、配对时按 case_id 对齐、训练种子独立统计，以及三图和汇总 CSV/JSON。实现 storage.py、report.py 与命令行 generate/prepare/run/report；附中文使用说明和三类策略配置示例，不包含伪造的模型成绩。
